How it works

Every AI chat starts cold — it doesn't know who you are, your stack, or how you learn. This system fixes that in two layers.

;;mentor is the base layer: paste it once at the start of a chat to set how the AI teaches you. The task snippets (;;go, ;;stuck, ;;review...) are small prompts for specific moments that work inside that chat.

Exceptions: ;;checkin is self-contained, so it works in a cold chat with no ;;mentor. ;;fix deliberately overrides mentor mode for one request. In a Claude Project, skip ;;mentor — paste the project prompt (last tab) once and every chat inside it is set up.
The full loop
;;mentor (once per chat) → ;;predict stress-test one decision
→ ;;go + ;;plan plan before code → build order
→ build: ;;pseudo then code → ;;stuck / ;;duck / ;;error / ;;fix when blocked
→ ;;wrap at end of session → ;;checkin to resume in a new chat
→ done: ;;review → ;;ready → ;;reflect

One chat per project or topic. When a chat gets long and the AI loses context, end it with ;;wrap and start fresh with ;;checkin.

Modes — the AI reads your signal
Teacher Mode (default)Triggered by: "how do I", "explain", "what is", "why does", or describing a problem. Guides with questions, no code.
Code ModeTriggered ONLY by: "show me", "write this", "give me the code". "I'm stuck" is not a trigger — ;;stuck means a nudge, not code.

Day-to-day workflows
Opening any new chat

Paste ;;mentor first. Then fire the snippet for what you're doing (;;go, ;;begin, ;;learn...). Resuming a project in a cold chat? Use ;;checkin alone — it carries its own role line.

Before you plan anything

Fire ;;predict with the single biggest decision you're about to make — one choice, not the whole project. Let it ask "what if" questions until your thinking holds up. Then move to planning.

Starting a new project

Fire ;;go with the project name, new concepts, and previous projects. It asks one question — "what data does this app need to remember?" — and waits. The build order unfolds from your answer.

Filling the architecture plan, then getting the build order

Fire ;;plan before any code: sections 1, 2, 3, 11 first. Before coding each feature, fire it again for sections 4, 5, 5b, 7, 8. When the doc is complete, paste it into the plan line of ;;go — it skips the question and gives you the smallest tasks in order. Task 1 first; don't skip ahead.

Building a feature

Write pseudocode first and check it with ;;pseudo. Then attempt the code yourself. After it works, use ;;explain to say the concept back in your own words and find the gaps.

You're stuck mid-build

Four levels, from least to most help:

;;stuck — slightly stuck: copy your code, get one nudge at a time
;;duck — really confused: talk it out, the AI asks questions back
;;error — red error message: understand it first, then fix it yourself
;;fix — just need to move: no teaching (overrides mentor mode for that one message)
Ending a session and resuming later

Fire ;;wrap at the end. You summarise what you learned, it points out what's shaky and writes notes. Next time, open a fresh chat, fire ;;checkin, paste those notes plus your code, and write your own guess at the next step before asking. That keeps decomposition a skill you practise.

Finishing something

;;review for what a senior dev would change, then ;;ready to test whether you actually understood it (it asks "what would break if..." questions). Then ;;reflect to close out the project and lock in lessons.

Feeling lost, or asking about Next.js

;;breathe when overwhelmed: one thing to focus on, one thing to ignore, one 30-minute task. ;;next before any Next.js question to lock in App Router, RSC, Shadcn tokens and TypeScript.
